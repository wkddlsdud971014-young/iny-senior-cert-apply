# Part A. 기능테스트

기능 하나씩 따로 꺼내서 작동하는지 확인합니다.

## 필수 - Must (전부 통과해야 완료)

- [x] **M1.** 배포 주소가 열린다 - Vercel 주소를 **시크릿 창 또는 폰**에서 열었을 때 접수 화면이 뜬다
- [x] **M2.** 자격증을 고를 수 있다 - 자격증 1개를 선택하면 화면에 선택 표시가 뜬다. 선택한 자격증: 한식조리기능사
- [x] **M3.** 접수 폼 제출 - 이름, 연락처 입력 후 접수 버튼을 누르면 에러 없이 제출된다
- [x] **M4.** DB에 저장됨 - Supabase Table Editor에서 방금 제출한 행이 보인다. 이름/자격증/연락처 일치
- [x] **M5.** 새로고침 후 잔존 - Supabase 대시보드 F5 후에도 행이 그대로 있다
- [x] **M6.** 어드민에서 조회 - admin 페이지를 열면 방금 접수한 내역이 표에 나온다
- [x] **M7.** 다른 자격증 재접수 - 다른 자격증으로 새 이름을 넣어 한 번 더 접수. DB에 행이 하나 더 생긴다
- [x] **M8.** 어드민에 2건 표시 - 어드민 새로고침 후 2건 모두 표에 보인다

## 필수 - Should (전부 통과하기)

- [x] **S1.** 이름 빈칸 차단 - 제출은 막힘. 다만 안내 문구가 버튼보다 한참 아래에 떠서 처음엔 못 봄 (위치 개선 필요)
- [x] **S2.** 자격증 미선택 차단 - 자격증을 안 고르고 접수 버튼 -> 안내가 뜬다
- [x] **S3.** 연락처에 글자 차단 - 글자가 입력되지 않게 막힘. 다만 「숫자만 넣어 주십시오」 같은 안내가 없어 왜 안 써지는지 알 수 없음 (안내 추가 필요)
- [ ] **S4.** 연락처 자릿수 부족 - FAIL: "010"만 넣어도 그대로 접수됨. 자릿수 검사가 없음
- [x] **S5.** 어드민 비밀번호 보호 - 시크릿 창에서 어드민 주소 -> 비밀번호 없이는 내역이 안 보인다. 비밀번호 없으면 "없음" 기록
- [x] **S6.** 틀린 비밀번호 차단 - 어드민 비밀번호에 "xxxx" 입력 -> 접근 거부
- [x] **S7.** 접수 후 어드민 실시간 반영 - 폼에서 1건 제출 후 어드민 새로고침 -> 방금 건이 추가됨
- [x] **S8.** 같은 사람 2번 접수 - 같은 이름, 같은 자격증으로 2번 -> DB에 2행 생김

## 선택 - Could (하면 가산점)

- [ ] **C1.** 폰에서 읽힘 - FAIL: 휴대폰에서 글자가 밀리고 겹침. 챗봇 예시 버튼을 누르면 답이 아니라 아래 입력칸으로 화면이 내려감

- [x] **C3.** 폼 초기화 - 접수 성공 후 입력값이 지워져 있다

# Part B. 시나리오 테스트

실제 사용자가 처음부터 끝까지 쓰는 흐름을 따라가면서, **어디서 막히는지**를 찾습니다.

## 필수 - 시니어 시나리오 (5개 중 3개 이상)

시나리오 속 인물이 되어 처음부터 끝까지 써봅니다. **"막힌 곳"을 반드시 적습니다.**

### US1. 요양보호사 접수하는 62세

> 김순자(62세)가 학원 직원에게 받은 링크로 요양보호사 시험을 접수합니다.

- [x] 링크를 눌러 접수 화면을 연다 - 뭘 해야 하는지 알겠다
- [x] 8종 중에서 요양보호사를 찾는다
- [x] 요양보호사를 선택한다 - 내가 고른 게 맞는지 표시된다
- [x] 이름 "김순자" 입력 - 글씨가 잘 보이고 입력칸을 찾겠다
- [x] 연락처 "01087654321" 입력
- [x] 접수 버튼 - 접수가 됐다는 걸 알 수 있다
- [x] 접수 완료 안내가 화면에 남아있다

막힌 곳: 없음  
글씨 크기 (팔 뻗은 거리에서 읽힘): o

### US2. 지게차 면허 갱신하는 68세

> 박영수(68세)의 지게차 필기 재응시를 학원 직원이 대신 접수합니다.

- [ ] 접수 화면에서 지게차운전기능사를 찾는다 - FAIL: 홈에서 「접수하러 가기」를 눌러야만 자격증이 보임
- [x] 선택한다 - 선택 표시가 뜬다
- [x] 이름 "박영수" 입력
- [x] 연락처 "01055551234" 입력
- [x] 접수 버튼 - 완료 표시
- [x] 어드민에서 "박영수 / 지게차운전기능사" 확인

막힌 곳: 접수하기 버튼을 눌러야만 지게차운전기능사 선택이 가능하다.

### US3. 학원 직원이 오늘 접수 건수 확인

> 직원 이지은(28세)이 오늘 몇 명이 접수했는지 어드민에서 확인합니다.

- [x] 어드민 주소를 연다 - 비밀번호 입력 화면이 뜬다
- [x] 비밀번호 입력 후 접수 내역 표가 보인다
- [ ] 오늘 접수 건을 셀 수 있다 - FAIL: 「오늘 접수」 건수 표시가 없음. 1,006건 중에서 눈으로 세야 함
- [x] 요양보호사만 보고 싶을 때 검색/필터가 있으면 사용, 없으면 눈으로 센다
- [x] 표를 아래로 스크롤한다 - 데이터가 잘리지 않고 이어서 보인다

막힌 곳: 요일별 필터가 걸려있지 않다.

### US4. 잘못된 정보로 접수 시도

> 실수로 엉뚱한 값을 넣고 접수 버튼을 누릅니다.

- [ ] 이름 "ㅎ"만, 연락처 비움, 접수 버튼 -> FAIL: 그대로 접수됨. 차단도 안내도 없음
- [ ] 이름 "ㅎ", 연락처 "010", 접수 버튼 -> FAIL: 그대로 접수됨. 차단도 안내도 없음
- [x] 자격증 미선택, 이름 "홍길동", 연락처 정상, 접수 버튼 -> 자격증 선택 안내
- [x] 전부 비우고 접수 버튼 -> 아무것도 안 들어간다

막힌 곳: 이름 오류, 연락처 오류 잡아내지 못하는 중

## 선택 - 엣지 케이스 (많이 할수록 좋음)

- [x] **E1.** 이름에 공백만 ("   ") -> 결과: 여기를 채워주세요 로 재안내
- [x] **E2.** 이름에 특수문자 ("!@#$%") -> 결과: 접수 가능
- [x] **E3.** 이름에 숫자 ("12345") -> 결과: 접수 가능
- [x] **E4.** 연락처 "00000000000" (0만 11자리) -> 결과: 접수 가능
- [x] **E5.** 연락처 17자리 이상 -> 결과: 17자리 이상 추가되지 않음
- [x] **E6.** 접수 버튼 3초 안에 5번 연타 -> 결과: 한 번만 인식됨
- [x] **E7.** 브라우저 뒤로가기 후 다시 제출 -> 결과: 한 번 제출 후에는 홈으로 뒤로가짐
- [x] **E8.** 어드민에서 F5 연타 5번 -> 결과: 오류 없이 정상 페이지 재작동
- [x] **E9.** 이름 50자 이상 -> 결과: 50자 이상 가능함 수정 필요
- [x] **E10.** 한글+영어+숫자 이름 ("김ABC123") -> 결과: 섞여서 수정 가능함
### US5. 한식조리 접수 후 확인 전화

> 이말순(71세)이 한식조리기능사 접수 후, 30분 뒤 학원에 전화해서 "접수됐나요?" 묻습니다.

- [x] 한식조리기능사 선택
- [x] 이름 "이말순", 연락처 "01033339999" 입력
- [x] 접수 버튼 - 완료
- [x] 브라우저를 닫는다
- [x] 30분 뒤 같은 주소를 다시 열었을 때 접수 화면이 뜬다
- [x] 직원이 어드민에서 "이말순"을 찾아 확인해줄 수 있다

막힌 곳: 없음. 「접수 확인」 화면에서 본인이 직접 확인할 수도 있음

### "요보사" 를 세 단계에 걸쳐 쫓은 결과

| 단계 | 결과 | 왜 |
|---|---|---|
| S4 키워드 | ❌ 2점 동점, ID 순서로 결정 | 자격증명이 안 맞아 큰 점수를 못 받음 |

**동의어를 뺀 S6 의 유사도(0.56)가 도전3 S5 의 값과 정확히 일치한다.**
같은 TF-IDF 이므로 당연한 결과이고, 동시에 **차이를 만든 것이 동의어 하나뿐**임을
보여준다. 검색 방식·데이터·프롬프트는 그대로다.

> **도전3의 결론이 여기서 증명됐다.**
> 검색 알고리즘을 바꿔서 풀리는 문제와, 사람이 아는 것을 넣어 줘야 풀리는 문제는 다르다.
> `포크레인` 은 상담 기록에 실제로 나오는 말이라 TF-IDF 가 스스로 해결했지만,
> `요보사` 는 데이터에 한 번도 안 나오므로 **어떤 검색 방식으로도 찾을 수 없다.**
> 사전 등록이 유일한 해법이었다.

> **곁가지 관찰**: 재추가 후 질문할 때 브라우저에 `Error - Could not parse server response:
> SyntaxError: Unexpected token '<'` 팝업이 한 번 떴다. 답변은 정상적으로 표시됐다.
> 서버 상태를 확인하니 로컬·공유 모두 200 이고 로그에도 오류가 없었다.
> JSON 을 기대한 자리에 HTML 이 온 것으로, **gradio.live 터널이 순간 끊겼다 붙을 때**
> 나는 증상이다. 기능 문제가 아니라 공유 URL 방식의 불안정성이다.
> 계속 살아 있어야 하는 서비스에는 이 방식을 쓰지 않는 또 하나의 이유다.

> 지운 FAQ 가 계속 답하는 유령이 되므로, 양방향을 함께 확인해야 한다.

### 4번에서 발견한 것 — 데이터 3,502건이 검색에 반쪽만 쓰인다

유사도 0.77 은 오늘 관찰한 값 중 두 번째로 높은데도 답하지 못했다. 검색 결과를 열어 보니
**1~3등 문서가 모두 내용이 비어 있었다.**

데이터는 두 출처를 합친 것이다.

| 출처 | 건수 | 칸 이름 |
|---|---|---|
| 게시판 `qna_board` | 1,203건 | `title` / `body` / `reply` |
| **전화 상담 `phone`** | **3,502건** | `opening` / **`exchanges`** (주고받은 대화 배열) |

그런데 `rag.py` 의 `_build_docs()` 는 이렇게 글자를 만든다.

```python
f"{cert} {category} {title} {body} {reply}"
```

**전화 기록에는 `title`·`body`·`reply` 가 없다.** 내용이 `exchanges` 안에 들어 있다.
그래서 실제로 만들어진 검색용 글자는 이렇다.

```
'공인중개사 HC 환불   '
```

자격증명과 카테고리만 남고 **내용이 통째로 빠진다.** 정작 그 안에는 답이 들어 있다.

> "환불은 접수기간 안에 취소하시면 100%, 5일 전까지는 50%, 4일 전부터는 어렵습니다."

`reply` 가 빈 문서가 **3,502건 / 4,705건 = 74%** 다.

### 왜 하필 유사도가 가장 높았나

문서가 `공인중개사 HC 환불` 세 낱말뿐이라 질문 `공인중개사 환불 규정` 과 거의 완전히 겹친다.
**짧은 문서일수록 코사인 유사도가 높게 나온다.**
**내용이 없어서 유사도가 높아지고, 내용이 없어서 답을 못 한다.**

### 유사도는 정답 여부와 나란히 가지 않는다

| 유사도 | 질문 | 결과 |
|---|---|---|
| **0.77** | 공인중개사 환불 규정 | ❌ 빈 문서 |
| 0.76 | 테스트 | ✅ |
| 0.66 | 굴착기 접수비 · 위생사 접수 | ✅ |
| 0.60 | 전기기능사 계산기 | ✅ |
| 0.56 | 미용사 시험비 (다루지 않는 자격증) | ❌ |
| 0.36 | 지게차 실기시험 | ❌ |
| 0.33 | 포크레인 접수비 | ✅ |

가장 높은 값이 가장 쓸모없는 문서였고, 가장 낮은 값이 정답이었다.
**도전3 C1(min_score 올리기)이 왜 위험한지에 대한 근거이기도 하다.**

### 고칠 곳

`_build_docs()` 와 `build_prompt()` 가 `exchanges` 를 읽도록 고쳐야 한다.
전화 기록의 `caller`·`staff` 대화를 이어 붙이면 3,502건이 제대로 검색된다.
지금은 데이터의 74%가 자격증명과 카테고리만으로 검색되고 있다.

## 도전4에서 확인된 것

**세 기능이 한 화면에서 함께 돈다.** 4,705건을 TF-IDF 로 검색하고, 공유 URL 로 바깥에서

### 실패 방식이 두 가지였다

| 질문 | 검색 | 답변 | 어디서 실패했나 |
|---|---|---|---|
| 굴착기 **시험비** | ✅ 3건 (각 4점) | ❌ UNKNOWN | **엉뚱한 문서를 찾았다** |
| **포크레인** 시험비 | ❌ 0건 (최고 1점, 문턱 2점 미달) | ❌ UNKNOWN | **아예 못 찾았다** |
| 굴착기 **접수비** | ✅ 정답 문서 5점 | ✅ 정상 | 정상 |

**① 굴착기 시험비 — 낱말이 데이터와 다르다**
상담 데이터에는 `접수비` 라고 적혀 있고 `시험비` 라는 말은 거의 쓰지 않는다.
그래서 `접수비` 로 물으면 정답 문서("굴착기 시험 접수비 질문")가 5점으로 1등이지만,
`시험비` 로 물으면 그 문서가 걸리지 않는다. 자격증명이 맞아 +3점은 받았으므로
굴착기 문서들이 올라오긴 했으나 주제가 전부 달랐다.

**② 포크레인 시험비 — 자격증명이 안 맞아 큰 점수를 못 받는다**
```python
cert_match = 3 if row["cert"] in question else 0
```
`포크레인` 은 `굴착기` 와 글자가 겹치지 않아 **가장 큰 점수 +3 을 통째로 못 받는다.**
`시험비` 도 데이터에 없어 카테고리 +2 도 없다. 남은 것은 겹침 1점뿐이라 문턱(2점)에도 못 미쳤다.

눈에 띄는 것은 1점짜리 후보의 제목이 **"굴착기 포크레인 명칭 문의"** 였다는 점이다.
데이터 안에 "포크레인이 굴착기가 맞나요"라는 상담 기록이 실제로 있는데도
점수가 낮아 버려졌다. **답이 데이터에 있어도 못 꺼내는 것**이 키워드 매칭의 한계다.

> 이 항목은 "무엇이 한계인지"를 정확히 하는 것이 목적이므로 질문을 두 개 던졌다.
> `굴착기 시험비` 하나만으로는 "데이터가 많아서 틀린다"로 잘못 읽힐 수 있다.
> 실제로는 **데이터 양이 아니라 부르는 이름과 낱말이 다를 때** 무너진다.
> 같은 데이터 4,705건에서도 `굴착기 접수비` 는 정확히 답한다.

### 40건에서 실패한 이유 — 1점 차이로 순위가 뒤집혔다

```
Q. 굴착기 시험비
   5점  굴착기운전기능사 시험과목   ← 1등 (엉뚱한 문서)
   4점  굴착기운전기능사 응시료     ← 2등 (정답 문서)
```

`answer_question()` 은 1등 하나만 Gemini 에게 넘긴다.
Gemini 는 「시험과목」 문서를 받고 시험비 얘기가 없어 거절했다.

| 문서 | 키워드 | "굴착기 시험비" 와 맞는 것 |
|---|---|---|
| **시험과목** | 굴착기, 포크레인, 과목, **시험**, 뭐, 공부 | `굴착기` +2, **`시험`** +2 |
| 응시료 | 굴착기, 포크레인, 응시료, **시험비**, 비용, 얼마 | `굴착기` +2, `시험비` +2 |

**`시험` 이 `시험비` 안에 들어 있어서** 「시험과목」도 같은 점수를 받고,
제목 겹침에서 1점을 더 챙겨 이겼다. 도전2 MUST 챌린지에서 겪은 것과 같은 현상이다
(그때는 `한식` 이 `한식조리기능사` 안에 들어가 기존 FAQ 가 8:5 로 이겼다).

### 질문을 길게 쓰면 맞는다

```
Q. 굴착기 시험비가 얼마예요?  → 6점으로 「응시료」가 1등  ✅
```

**짧게 물으면 틀리고 길게 물으면 맞는다.**
시니어 사용자는 짧게 묻는 경우가 많으므로 실제 서비스에서 중요한 문제다.

> **문서의 기대("40건은 정확, 4,705건은 부정확")가 맞지 않았다.**
> 데이터가 많아져서 나빠지는 것이 아니라, **키워드 매칭이라는 방식 자체가**
> 흔한 낱말이 겹칠 때 순위를 잘못 매기는 것이다. 40건에서도 똑같이 일어난다.
> 4,705건에서는 그 일이 더 자주 일어날 뿐이다.
>
> 참고로 두 데이터는 성격도 다르다. 40건짜리 `faq.json` 은 학습용으로 정리된
> 것이라 `시험비` 가 키워드에 들어 있지만, 4,705건은 실제 상담 기록이라

### 한 건 맞은 것도 우연이었다

TF-IDF 가 세 질문에 대해 **똑같은 문서 3개**를 가져왔다.

```
포크레인 시험비 → 한식조리 / 전기 / 손해평가사  시험비 문의
굴착기 시험비   → 한식조리 / 전기 / 손해평가사  시험비 문의   (동일)
한조기 시험비   → 한식조리 / 전기 / 손해평가사  시험비 문의   (동일)
```

자격증명이 순위에 아무 영향을 주지 못하고 있다는 뜻이다. 확인해 보니

```
Q. 시험비          (자격증명 없이 이 낱말 하나만)
   0.56 [한식조리] 한식조리 이론 시험비 문의      ← 1등
   0.55 [전기]     전기 시험 시험비 질문
   0.55 [손해평가사] 손해평가사 시험 시험비 질문
```

**"한조기 시험비" 의 결과와 유사도까지 완전히 같다(0.56).**
`한조기` 는 TF-IDF 사전에 없는 낱말이라 통째로 버려졌고, 실질적으로 `시험비` 하나만
물은 셈이었다. 그런데 `시험비` 의 1등이 우연히 「한식조리」였고,
`한조기` 가 가리키는 것이 마침 한식조리라서 **정답처럼 보였다.**

| 질문 | 자격증명 처리 | 결과 |
|---|---|---|
| **포크레인** 시험비 | 사전에 있는데도 힘이 약함 | ❌ 한식조리 문서 |
| **굴착기** 시험비 | 사전에 있는데도 힘이 약함 | ❌ 한식조리 문서 |
| **한조기** 시험비 | 사전에 없어 **버려짐** | ⭕ **우연히** 한식조리 |

### 왜 자격증명이 힘을 못 쓰나

```
"시험비" 가 들어간 문서: 130건 / 4,705건  → 아주 희귀 → IDF 매우 높음
```

TF-IDF 는 드문 낱말에 큰 힘을 준다. `시험비` 는 4,705건 중 130건에만 있어
힘이 매우 크다. 반면 `굴착기` 는 상담 기록에 수백 건 나와 상대적으로 약하다.
**희귀한 `시험비` 하나가 자격증명을 눌러 버렸다.**

> **S4 와 S5 는 방식이 다른데 증상이 같다.**
>
> | | S4 키워드 | S5 TF-IDF |
> |---|---|---|
> | 실패 원인 | `시험` 이 `시험비` 안에 들어 있어 엉뚱한 문서가 이김 | `시험비` 가 너무 희귀해서 자격증명을 눌러 버림 |
> | 공통 증상 | **한 낱말이 순위를 지배해 자격증이 어긋난다** | 〃 |
>
> 그리고 이번에는 **우연한 정답**까지 섞여 판단을 더 어렵게 만들었다.

## 도전3에서 확인된 것

**검색 방식을 바꾸는 것만으로는 부족하다.**

키워드 매칭과 TF-IDF 는 방식이 다른데 **증상이 같았다.**
한 낱말이 순위를 지배해 자격증이 어긋난다. 키워드는 `시험` 이 `시험비` 안에 들어가서,
TF-IDF 는 `시험비` 가 너무 희귀해서. 원인은 다르지만 결과는 똑같이 엉뚱한 문서였다.

**TF-IDF 가 이기는 자리는 분명히 있다.** `포크레인` 처럼 상담 기록에 실제로 나오는 말은
희귀 낱말로 인식해 정확히 찾는다(S4 실패 → S5 성공). 하지만 `요보사` 처럼
**데이터에 아예 없는 말은 어떤 검색 방식으로도 찾을 수 없다.**
그것은 사람이 사전에 등록해 줘야 풀린다 — 도전4 에서 확인한다.

**그리고 "맞았다"를 그대로 믿으면 안 된다.**
오늘 우연한 정답을 두 번 만났다. 화면만 보면 챗봇이 줄임말을 이해한 것처럼 보이지만,
점수를 열어 보면 그 낱말을 버린 채 다른 이유로 맞은 것이었다.
정답률만 세면 잘못된 결론에 이른다.

**마지막 방어선은 두 겹이다.**
① 검색 점수가 문턱에 못 미치면 Gemini 를 아예 부르지 않는다
② 근거를 받아도 질문과 맞지 않으면 Gemini 가 거절한다
"미용사 시험비"(S3)처럼 검색이 헐거워 관련 없는 문서가 넘어간 경우에도
②가 막아 주어 잘못된 안내로 이어지지 않았다.
